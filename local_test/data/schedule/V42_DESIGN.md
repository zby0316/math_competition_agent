分支：v33（本地）

## 1. 动机（V4.1 回放仿真暴露的缺口）

V4.1（双独立代码验证）救回 4/34 规则可判定错题，但两类仍救不了：

| 缺口 | 数量 | 案例 | 失败模式 |
|---|---|---|---|
| A. 同源同错（match 出厂） | 3 | #0 py=rz=2≠3、#96 py=rz=8≠12、#104 py=19/30 | 推理+Python 同一错误方向，"双闭式等价"反而掩盖错误 |
| B. Python 不可用 | 11 | #5/#6/#8/#17/#19/#56/#68/#88/#97 等 | 代码生成失败/截断/非闭式输出，无第二证据 |

A 类：需要**独立采样的多票**打破同源一致性（不同温度/提示的多次求解，
多数投票）。B 类：需要**重试/替换策略**让代码这条路重新走通，或推理侧
多采样投票。

## 2. 设计（AIMO2 路线：SC + 早停，预算友好）

### 2.1 触发条件（不扩大预算消耗）
只在以下情况对**规则可判定题**触发 SC：
- 出厂时 validation_status == match 且 **python 闭式与推理闭式数值等价**
  （同源同错高风险：等价但不一定对——V4.1 回放 6/6 同错的形态）
- 或：python 不可用（attempts>=2 全失败）+ 规则可判定 + 剩余硬预算 >= 600s

### 2.2 采样协议
- 独立采样数：**3 份**（n=3），与主链路完全隔离（无候选注入、无共享上下文）
- 采样方式：温度 0.7 / 0.9 / 1.1 三档（temperature 参数），同一独立求解提示
  （提示 = 题面 + "用完全不同的方法求解，只输出答案和简述"）
- 早停（AIMO2）：采样到第 2 份时若与前一份一致 → 停止，直接锁定
  （一致性 = 闭式数值等价，复用 rule_judge.answers_numerically_equivalent）
- 投票：3 份采样 + 主链路候选（共 4 票）→ 取多数；平票时取与 python 闭式
  一致方（python 闭式在 V4.1 已验证过）

### 2.3 接入点（graph/solving_subgraph.py）
新节点 `sc_consensus_node`，插入位置：coordinator 之前（validation 之后）。
- 输入：state（含 validation_status / validated_answer / 触发标志）
- 输出：state["sc_consensus"] = {samples, votes, adopted, reason}
- coordinator 若 sc_consensus.adopted 存在 → 用它作为 final_response 答案
  （附 SC 说明），answer_locked=True

### 2.4 成本预算
- 每道触发题最多 3 次短采样（max_tokens 4096，~90s/次）→ 上界 ~4.5min/题
- 只对规则可判定题触发（占 112 题的 ~57% 中的小部分：match+等价或
  python 不可用，预计 10-20 题/轮）
- 预算闸门：remaining_hard > 600s 才触发（与 V4.0 hard_verify_forced 同款）

### 2.5 预期收益（round3 回放估算）
- A 类 3 题：3 份独立采样中若 ≥2 份算出正确值（#0=3 是简单题，独立采样
  大概率对）→ 救回。期望 ~2-3/3。
- B 类 11 题：独立采样本身就是新的求解尝试（不依赖 python 分支），
  期望 ~30-50% 救回率（这些题难度分布中 hard 占比高）。
- 合计期望 +2~6 分/轮（保守 +3）。

## 3. 风险与对策
- 采样同错（同源）：温度扰动无法完全打破——3 份全错的概率低于单份，
  且投票要求多数（4 票中 3 票），保守。
- 预算超支：早停 + 预算闸门 + max_tokens 4096 上限三重保护。
- 与 V4.1 双验证的交互：触发条件互斥（SC 触发 = 已 match 或 py 不可用，
  双验证触发 = 未 match 且有 py 闭式）。
