# V4.6 设计：SC 多采样 + Code-First 投票（破解能力边界）

日期：2026-08-25（实验验证中，数据就绪后实施）
分支：v33

## 1. 动机

round4 的 47 题重测仍错 = 模型 397B 单次推理深度不足（同源同错/构造难/
中途错）。验证层（V4.1 双验证/V4.5 防线）只能筛选候选，不能创造新候选。
破解方向：**增加有效推理深度**——多视角采样 + 程序化主解 + 投票。

## 2. 方案（AIMO2 银牌路线 + 双扰动）

### 2.1 3 视角推理采样
- 温度 0.7/1.0/1.3 × 方法提示扰动（代数/构造/枚举）
- 早停：第 2 份与第 1 份闭式等价即停（AIMO2 early stopping）
- 结论先行格式（V4.3 同款章节序，`## 最终答案` 前置）

### 2.2 3 份独立代码求解（Code-First）
- 算法扰动：暴力枚举 / sympy 符号 / DP 递推
- 代码执行提取 `最终答案:`（本地实验 subprocess；生产走 MCP 沙箱）
- 早停：两代码结果等价即停

### 2.3 投票与锁定
- 推理投票 vs 代码投票分别统计；任一通道 ≥2 一致 → 锁定该答案
- **双通道判定**（冒烟 #1/#7 实证修正）：文本答案题（博弈必胜/收敛发散/函数
  类）不走闭式——新增**文本等价通道**（去空白/标点后一致，len≥3）；
  闭式或文本任一通过即视为同一答案
- 双通道一致（推理 2/3 == 代码 2/3）→ 最高置信
- 全部不一致 → 不锁定，走原链路（不更差）

### 2.4 预算纪律（官方 6h 合规）
- 只对"未 match 且 hard 且 规则可判定/计算类"的题触发
- remaining_hard < 600s 不触发（单题 1200s 硬限内留 SC 空间）
- 每份 max_tokens 4096（~90s），早停上限 3 份
- **TimeBudget 每题独立**（实验 bug 实证：全局共享会撞 26 次/题调用 cap）

## 3. 接入点（实验确认后）

新节点 `nodes/sc_consensus_node.py`，插在 cross_validator 与 coordinator 之间：
- 输入：state（problem/validation_status/difficulty/rule_judgeable）
- 输出：sc_consensus（samples/votes/adopted）+ answer_locked
- solving_subgraph 接线 + config 开关 `enable_sc_consensus`

## 4. 预期收益（round3/4 数据外推）

- 47 题中计算/枚举/博弈类 ~25 题：代码投票预期救回 30-50%（8-12 题）
- 推理采样对构造/证明类：预期 10-20%（2-4 题）
- 合计 +10~16 分潜力；双通道全败时与现状持平（零风险）

## 5. 实验（已完成，2026-08-25）

`local_test/sc_experiment.py`：47 题 × (3 推理 + 3 代码)，8 并发，30 min。

### 结果：救回 5/47（#14 #34 #55 #63 #87）

| 题 | 官方 | 命中通道 | 说明 |
|---|---|---|---|
| #34 | ln 2 | 双通道 | 推理 ln2 + 代码 log(2) 一致（V4.1-V4.5 全错过） |
| #55 | 2/3 | 推理 | 两视角 2/3 一致（原候选全错 5/9，采样打破同源） |
| #87 | 0,±i√6 | 推理 | 两视角一致 |
| #14 | -1/8 | 代码 | brute 代码 -0.125（原 python 失败） |
| #63 | 三角式 | 代码 | sympy 符号代码成功 |

### 洞察
- 3 视角推理的价值：**打破同源**（#55/#87 之前三路候选同错）
- 3 份代码的价值：**算法互补**（#14/#63 原 python 全失败）
- 双通道一致（#34）是最强锁定信号
- 42 题仍错：SC 也救不了（模型单次推理在这些题上就是错的）
- **预期收益：+5 分/轮**（对"重测仍错"最难子集）

## 6. 主图接入方案（实验确认版）

### 6.1 触发条件
- validation 未 match（uncertain/mismatch 路径）
- difficulty == hard 或 规则可判定
- remaining_hard > 600s（单题 1200s 硬限内留 SC 空间）
- config 开关 `enable_sc_consensus`（默认 True）

### 6.2 执行顺序（预算感知）
1. 3 视角推理采样（代数/构造/枚举，温度 0.7/1.0/1.3，早停：2/3 一致即停）
2. 未一致 → 3 份代码求解（brute/sympy/dp，早停：两代码等价即停）
3. 任通道 ≥2 一致 → 锁定（answer_locked=True, sc_consensus 记录）
4. 双通道一致 → 最高置信
5. 全不一致 → 不锁定走原链路（不更差）

### 6.3 实现
- 新节点 `nodes/sc_consensus_node.py`（插在 cross_validator 与 coordinator 之间）
- `_same_answer`：闭式等价或文本等价（去空白/标点）
- solving_subgraph 接线 + config 开关
- 记录：sc_consensus（samples/votes/adopted/reason）入 trace
