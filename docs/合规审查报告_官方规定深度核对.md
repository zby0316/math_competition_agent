## 四、发现的问题（2 个，均非红线）

### 问题 1（轻微）：config.py 模型名带 `-397b` 后缀

- 官方文档列出的模型是 `intern-s2-preview`（**无 `-397b` 后缀**）
- 项目 `config.py` 写的是 `"model": "intern-s2-preview-397b"`
- **影响评估**：该字段仅被 `llm_client.py` 的**本地调试 client** 使用
  （`DEFAULT_MODEL`）；正式评测由平台注入官方 client，模型由平台选定，
  `user_agent.py` 完全不引用 `llm_client`，**不影响正式评测**。
- **建议**：本地调试时若 API 报模型不存在，用环境变量
  `export INTERN_MODEL="intern-s2-preview"` 覆盖即可，无需改代码。

### 问题 2（提示）：官方文档未明确"并发 3"和"6 小时"数字

- 官方 PDF 中**只有**单题 20 分钟是明确数字（第 864 行、3280 行）
- 全卷 6 小时、并发 3 是**之前从其他渠道（官方答疑/群通知）获得的规则**
  （已记入项目 MEMORY），PDF 知识库文档中未出现这两个数字
- 文档仅说"平台会统一控制超时、并发、模型调用预算和资源限制"、"可能设置
  一定并发，例如同时启动若干进程 slots"
- **影响评估**：项目按"并发 3 + 6h"的**更严格**假设设计（全卷目标 5h），
  若官方实际更宽松（如本地 runner 默认并发 8），项目只会更安全，不会失分。
- **建议**：保持现状即可，无需调整。
