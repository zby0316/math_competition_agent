## 〇、先决条件：0 分防线（已落地并实测）

启元原项目连续 4 次提交 0 分的根因（评测 CSV 实证）：
**112 题全 error、0 次 API 调用**——平台沙箱加载器 `exec` 时不设 `__file__`，
薄壳自举裸引用 `__file__` → NameError → 整个 `user_agent.py` 加载失败。

**VeritasMath 防线（三形态实测全安全）**：
| 加载形态 | 结果 |
|---|---|
| 正常 import | ✅ graph 正常出答案 |
| importlib 路径加载（不加 sys.path） | ✅ graph 正常出答案 |
| exec 无 `__file__`（启元 0 分形态） | ✅ graph 正常出答案 |
| exec 无 `__file__` + CWD 不在仓库（最严苛） | ✅ fallback 兜出真答案 |

**本轮关键修复**：fallback 兜底从"import utils.response_normalize"改为**完全自包含**
（归一化+签名探测内联）——否则核心图加载失败时 utils 同样不可达，兜底形同虚设。
已固化为永久门禁 `test_harshest_exec_no_file_foreign_cwd`。

## 二、冲刺满分的机制（按剩余失分点设计）

### M1【已落地】确定性复算裁决（contradict 假证据）
idx=30 类：Python 算错却自报反驳正确推理。contradict 先送 playoff 代回复算，
证据闸门在 playoff decisive 后豁免。**收益：仲裁选错类失分清零。**

### M2【已落地】输出层提取洁净度
idx=63 类：思维流中"依据："证据行被当答案。行号前缀剥离 + 证据标签行
（依据/理由/说明）+ dangling 收尾（故/因为/由于）双重过滤。**收益：提取污染清零。**

### M3【已落地】判断题双向确认
Intern-S2 系统性偏"否"（启元实测 90% 判断错题同根因）。结论→温度0独立自证
→一致采纳/反向温度0重解。**收益：判断题（21 题占 19%）方向错误大幅减少。**

### M4【已落地】推导矛盾自检 + 过程审计
链内同变量两值→矛盾触发定向修复；契约完整性审计门保多问/枚举/区间不漏。
**收益：推理策略分 + 完整性失分。**

### M5【下一步，攻能力边界】数值题答案代回验证
针对 idx=13 类（符号错）：对 fill/calc 数值题，把候选答案**代回题面条件**
做确定性验证（如导数题：对候选值数值验证左/右导数定义极限）。
- 触发：fill/calc 且 python 路径未给出 PASS 证据时；
- 成本：一次沙箱执行（≤60s），无 LLM 调用；
- 预期：符号类/边界类真错约一半可被抓出并触发重算。

### M6【下一步，攻能力边界】组合计数小规模枚举对照
针对 idx=40 类（计数错）：python_agent 对计数题**强制**先做 n=2,3,4 小规模
暴力枚举，与候选闭式逐点 assert 比对，不符即触发重算而非直接采信。
- 依据：组合计数是 LLM 最弱项，但小规模枚举可机器验证；
- 成本：枚举在小规模多项式时间内；
- 预期：计数类真错显著下降。

### M7【下一步】符号约定显式化
针对 idx=101 类：对含定向/符号约定的答案（曲率/法向/方向导数），
在最终答案中显式注明所采用的定向约定（"取外法向时 H=1/4"），
让官方语义 judger 无论何种约定都能判对。

## 三、诚实边界（不画饼）
- 59-60 分意味着错 ≤1-2 题，剩余失分已是 Intern-S2 的能力边界（组合计数、

- 所有机制都有 config 开关，关闭即退化，不引入新风险。

### M8 补充（治本机制，真机验证后追加）
`utils/verify_router.py`：填空题细分——纯概念填空（术语/定义）保持快速路径零成本；
