# VeritasMath（思鉴）：多径推理与过程审计数学智能体
## —— 基于 Intern-S 系列模型的数学智能体设计与推理创新 · 技术方案

**赛题编号**：XH-202627　**赛道**：挑战杯人工智能赛道（初赛）
**基线参照**：公开 LangGraph 图架构数学智能体基线
**目标**：在统一闭源评测集（112 题、18 个子领域）上实现更高答案正确率

---

## 一、问题理解与判分机制分析

### 1.1 任务

基于 Intern-S 系列模型 API 构建数学智能体：输入自然语言数学题（含 LaTeX），
自主规划求解并输出结构化 JSON（`final_response` + `trace`）。评测集 112 题，
覆盖 18 个子领域，分布不均（离散数学 21.4%、数值分析 11.6%、测度积分 9.8%、
微分几何 8.0% 等）；题型含计算、推导、证明、解释、选择、填空，单题独立无多小问。

### 1.2 判分口径（决定设计方向的三条事实）

1. **初赛完全客观评分**：100 分制，judger 为 Intern-S 系列模型（2026-08-12
   官方规则更新），结合参考答案与解题过程综合判定（非字符串匹配，等价表达判对）；
   `final_response` 与 `trace` 均为 judger 输入。
2. **硬资源约束**：单题 20 分钟；智能体总运行 6 小时、平台并发 3——
   折算下来**平均每题可用约 9.6 分钟**，超时未答题不计分。
3. **环境约束**：评测 Docker 运行时断外网；仅安装 `requirements.txt` 声明的
   Python 包；只允许官方 Intern-S API；禁止大量简单 rollout 刷答案。

结论：本赛题的本质是「**在严格时间预算内最大化单题正确率**」，
设计重心必须放在 (a) 消除单样本推理错误、(b) 验证与纠错机制、
(c) 全局时间预算的最优分配，而非提示词堆叠。

### 1.3 基线方案剖析（我们站在哪里）

参考基线为 LangGraph 图架构：领域分类 → 双路并行求解（LLM 推理 ∥
Python/SymPy 验证）→ 交叉验证 → 调解重试 → 匿名语义仲裁 → 协调成稿，
辅以 18 领域技能手册、预填充加速、墙钟预算与多级兜底。其工程韧性极强，
结合基线公开的实测复盘，其残余失分集中于：

- **单样本强偏差**：模型在同一错误思路上重复犯错，重跑同一提示无信息量
  （如 F₂ 值域六值按普通整数求和）；
- **仲裁只能"选"不能"算"**：两候选冲突且各错一半时，系统被迫二选一
  （曾输出被自家程序枚举反驳的答案）；
- **契约检查靠手写正则**：多问漏答、空位缺漏等完整性问题必然漏网；
- **预算分配无难度观**：简单题与竞赛压轴题吃同一额度的软预算，
  在 6 小时全局约束下挤占难题资源。

## 二、系统设计：VeritasMath 架构

### 2.1 总体拓扑

```
input → classifier(领域+难度画像) → solving 子图
   ├─ reasoning_agent（主路径·直接法）
   ├─ reasoning_agent（B 路径·异构方法，条件触发）
   └─ python_agent（SymPy 独立验证）
→ cross_validator（三路比对）
   ├─ match ────────────────► critic ─► coordinator
   ├─ mismatch(计算题) ──────► playoff ─► critic / reconciliation / arbiter
   ├─ mismatch ──────────────► reconciliation（换方法重算）─► solving
   └─ uncertain ─────────────► semantic_arbiter（三候选）─► critic
critic ─► pass: coordinator / 缺口: reconciliation（定向修复）
```

核心拓扑性质：**任何答案进入成稿前必经过程审计门**；**计算题冲突先做
确定性复算，再决定是否付出整轮重算**。

### 2.2 五大新机制

#### 机制一：异构双方法推理（打破单样本强偏差）

第二推理路径以 `DIVERSE_METHOD_HINT` 强制切换方法论——构造枚举（小规模找规律）、
不变量与极端原理、反向归谬、生成函数/递推——与主路径的直接代数法形成
**方法论独立**的双证据。触发是条件式的以控成本：首轮仅高风险领域
（离散数学、非基础及进阶课程、微分几何、测度积分）并行；重算轮一律追加。
三路比对时"第二路径 ∧ Python 一致"直接采纳，强于任何单路径。

#### 机制二：过程审计智能体 Critic（把"完整性"从提示词升级为架构保证）

定稿前两级审计：(1) 题面契约完整性——确定性正则契约与 prefill LLM 审计
（~15s）保守合并，任一方报缺即缺，覆盖多问项、枚举全列、区间双端点、
检验结论、极值构造对、"最小常数"双侧论证等交付物；(2) 关键计算抽核——
独立复算 1~3 个中间步骤，`calc_error` 触发重算。缺口转为**定向修复提示**
回调解阶段（独立轮次计数封顶，防死循环）；修复通道关闭时，缺口清单显性
追加进成稿提示，完整说明成为最后补齐机会。

#### 机制三：确定性复算季后赛 Playoff（从"只能选"到"先算清楚再选"）

候选冲突时不重解原题，只做**候选代回核验**：方程回代残差、极值目标值实测+
约束可行性、计数小规模暴力枚举对照、存在性构造搜索。裁决 `A/B/BOTH` 直接
锁定；`NEITHER`（双证伪）带证伪信息触发换方法重算；`INCONCLUSIVE` 回退
既有通道。成本 ~200s，远低于整轮重跑 ~600-900s；每题至多一次，结构上无循环。

#### 机制四：难度感知动态预算（全局 6 小时约束的最优分配）

分类预填充顺带输出难度画像（边际成本≈0），软预算按 easy/medium/hard =
480s/840s/1200s 收紧，客观题一律 easy。软预算只决定可选阶段购买力；
平台 1200s 硬限永不下调，进行中调用不被截断，reserve 配额通道
（压缩重试/仲裁/应急直答）照常。期望全卷平均 ≤ 9.6min/题，难题拿满资源。

#### 机制五：模结构确定性守护（F₂/Z_m 语境三重防线）

检出"有限结构信号 + 聚合动作信号"同时出现时：(a) 向 Python 提示注入
"结构内聚合"强制条款；(b) 生成代码静态核查取模/异或证据，缺失打回修复；
(c) 执行输出要求打印"结构核验"行。针对评委实录的 F₂ 求和错误形态。

### 2.3 工程加固

- **符号等价判定**：`simplify` 8s 限时（超时降级采样，不再卡死关键路径）；
  自由符号异名时按基数相等尝试重命名映射后采样；采样维度上限升至 4。
- **客观题复核投票**：空位覆盖不足等低置信形态触发一次独立短采样比对，
  一致提置信，分歧保留更完整一方。
- **执行沙箱**：危险能力静态拦截（subprocess/socket/文件写/环境变量读取等，
  放行 `sys.setrecursionlimit` 等竞赛常用操作）；POSIX RLIMIT_AS 2GB +
  RLIMIT_CPU + 独立进程组整组回收。
- **trace 全留证**：难度画像、第二路径、季后赛裁决、审计缺口、复核投票、
  模守护命中全部结构化入 trace，支撑 judger 边缘判定。

### 2.4 继承自基线的韧性底座（原样保留）

预填充加速（分类 ~1s、仲裁 ~0.8s）、按实测耗时定价的重试、分级熔断与
压缩重试、结论捞回与洁净度终门、证据优先闸门、反伪造静态检查、
答案契约检查、应急直答、断点续跑、节点硬超时钳制于单题 deadline。

## 三、创新点总结（对应评审维度）

1. **推理策略与系统设计**：提出"多径生成 → 确定性复算 → 过程审计"三段式
   闭环，把答案正确性从单次采样概率事件转化为多机制串联的过滤管道；
   图拓扑上 Critic 为必经审计门，Playoff 使重算从第一反应降级为兜底手段。
2. **创新性**：确定性复算季后赛（候选代回裁决）与难度感知软预算
   （对 6h×3 并发全局约束的显式优化）均为区别于已有方案的机制级创新；
   异构方法约束以零额外采样成本注入方法论多样性。
3. **可扩展性**：全部新机制经 `config.py` 独立开关，关闭即退化为基线；
   新增领域只需补技能手册目录；机制与模型解耦，可随 Intern-S 新模型平滑升级。

## 五、风险与已知边界

- Playoff 对证明/概念题返回 INCONCLUSIVE（无法机械核验），退回语义仲裁；
- 难度画像误判只改变可选阶段购买力，不截断进行中的求解；
- 复核投票在两票同错时不提升正确率（独立性降低而非消除相关错误）；
- 模结构守护检出保守，未命中变体语境依赖提示层清单兜底；
- 沙箱为**纯正则黑名单**（已知风险）：官方题集无恶意题面，已评估暂缓 AST 白名单，
  初赛后加固；黑名单覆盖 subprocess/socket/os.system/写模式 open 等并有平台防线
  测试守护；
- det_solver / sympy 事前求解**未命中时回退 LLM**（证明题、自然语言无裸算式），
  命中但自验不过时同样交回 LLM，绝不劫持；
- 截断续写受预算闸门约束，极端慢 API 下仍可能无法补全（`_looks_truncated` 为
  保守判据，宁可多续一轮也不放行截断答案出厂）。

### 6.5 V2.4：prefill 抑制 CoT + 判分口径对齐 + 客观题格式兜底（2026-08-14）

V2.3 两套 112 题验收 96.4%/97.3% 后，进入 V2.4 针对官方环境的最后一轮优化。
三个核心：

#### （1）prefill 抑制 CoT（核心提速）

Intern-S2 模型的私有思维链（CoT）计入 `max_tokens`，官方慢 API（35s/请求）
下单次 reasoning 实测可到 **811s**（16384 token），是 V2.1 官方 40.18 分
（19 error + 22 invalid 全灭）的根因之一。V2.4 用 `chat_prefilled` 预填
开头（reasoning 用 `## 问题分析`、python 用 ```` ```python ````）让模型跳过
CoT 直接作答，思考引导改由提示词内化承担——**单次调用 811s → 41-77s
（约 10 倍提速）**。10 题 L4 难题真机验证 100% 正确 + 平均 3.8min。

#### （2）判分口径对齐（针对 V2.4 全量评测 2 道错题根因）

| 错题 | 根因 | 修复机制 |
|---|---|---|

#### （7）cap 适配：max_tokens ≤8192（批8，`efb41d2`，官方 56.25% 退步根因）
