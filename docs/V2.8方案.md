# V2.7 / V2.8 升级方案：破解"零提分"的结构性修复

> 2026-08-16 · 起源数智（XH-202627）
> 前置阅读：`docs/V2.6方案.md`（三连证伪）、`docs/STRESS_REPORT.md`（官方评测轨迹）

## 1. 背景：V2.6 官方实测 53.57 分（零提分）

V2.6（深度反思环 + token 上调 + 判分器对齐 + fix_hint 去锚定）官方实测零提分，
反而比 V2.4 第一次（59.82）掉 7 题。官方 eval 日志三个硬证据：

```
V1:   60 correct = 53.53 分
V2.1: 45 correct = 40.18 分（超时事故）
V2.4 第一次: 67 correct = 59.82 分（commit 7d38074）
V2.4 第二次: 60 correct = 53.57 分（commit 60aaa9b，同代码 ±6 分题集波动）
V2.6: 60 correct = 53.57 分 ← 反思环 + token 上调全失效，retry_count=0
```

| 硬证据 | 数据 | 揭示 |
|--------|------|------|
| `retry_count=0` | 反思环从未触发重算 | 反思 LLM 与主模型同源，模型错的题反思也判 correct（漏判） |
| `truncated=112`（10.2%） | 与 V2.4 的 91 同比例 | token 上调没降截断，根因是 CoT 塞满 max_tokens（无底洞） |
| completion 平均 2047 token | 答案普遍短 | 大量答案本来就没写全 |

**核心死结**：反思 LLM 和主模型是同一个 Intern-S，会的都判对、不会的也都判对，
反思环无法提供"比主模型更强的第二视角"，永远 retry=0。

## 2. 破解钥匙：精读官方 87 页 PDF 的三个关键发现

| 发现 | 官方原文 | 破解的死结 |
|------|---------|-----------|
| 思考模式可用 | 「可以使用模型的思考模式吗？A：可以」 | truncated（prefill 抑制思考是方向性错误） |
| 不限制 token | 「平台不额外限制单题 token 数量」 | 截断根因（max_tokens 给不足） |
| SymPy 可用 | 「允许使用 SymPy 等本地库」 | retry=0（机器代回是"硬验证"，不依赖同源 LLM） |
| 离线 RAG 可用 | 「离线 RAG、SymPy 可以使用，不能联网检索」 | 知识库"开卷"合规依据 |

## 3. V2.7：给足 token + SymPy 代回 + RAG 注入量 4 倍

### 3.1 给足 token（破解 truncated）

- 官方明确"不限制 token + 可用思考模式"→ 把 max_tokens 给足
- `reasoning_tokens_by_difficulty`：medium 16384→24576、hard 24576→32768
- 根因：官方 client 可能忽略 prefill 种子 → CoT 回来 → 塞满 max_tokens → 答案截断

### 3.2 SymPy 代回硬验证（破解 retry=0）

反思判 correct 后，额外做**机器代回**：生成"答案代回原题"的 sympy 代码 → MCP 执行
→ 解析 VERIFY_PASS/FAIL/NA。代回不成立（FAIL）→ 触发重算。

- 真机验证 5/5 全对：x²=4 答 x=3→FAIL（抓错）、答 ±2→PASS、1 到 10 求和 55→PASS、
  54→FAIL（抓差一）、证明题→NA（正确跳过）
- 核心洞察：代回代码是"机械操作"（代入→sympy 算残差），比"LLM 心算判断对错"可靠

### 3.3 RAG 注入量 4 倍（破解"闭卷"）

| 注入点 | 旧 | 新 |
|--------|-----|-----|
| 主求解 | 3000 | 12000 |
| 复核重试 | 2200 | 8000 |
| Python 验证脚本 | 2000 | 4000 |
| Python 知识参考 | 1600 | 4000 |

## 4. V2.8：释放深度思考 + 修复 RAG 失效 + 知识库三层覆盖

### 4.1 thinking_mode 深度思考（核心突破）

**根因**：V2.4 起一直用 prefill 强制模型"从不打开 reasoning_content 块"（跳过深度
思考直接作答）。而 Intern-S 的核心能力就是深度推理（reasoning_content）。

**修复**：主推理、反思环开 `thinking_mode=True`，释放深度思考能力。

**真机验证**：
- 有限域 F₈₁ 题 44.7s 答对 72（非当年无控制 CoT 的 811s）
- 10 道 L3/L4 科研级题 **10/10 全对**，含 v26 曾答错的 2 类题（S₃ 中心阶"多问漏答"、
  洛朗展开"答非所问"）——这两类正是"抑制思考"的后果

### 4.2 RAG 检索正则修复（从 V1 埋的 bug）

**根因**：`skill_excerpt.py` 的 `_MODULE_RE` 只识别 `## 模块` 和 `## 数字.` 两种标题，
但 18 领域文档实际用了 4 种格式。导致 12 个领域（复分析/常微分/概率论/抽象代数/
微分几何/拓扑/泛函/统计/线性回归/高代/数分/随机）的"关键定理速查表"被埋在 preamble，
检索走 fallback 只截头部——**核心公式从 V1 起从未被喂给模型**（复分析/常微分甚至
模块数=0）。

**修复**：`_MODULE_RE` 改为 `^##(?!\#)\s*\S`（匹配所有 `##` 二级标题）。
修复后 18 领域 preamble 全部降到 12-312 字符，模块数正常（复分析 0→14、常微分 0→5、
微分几何 10→33）。

### 4.3 知识库补全 15 领域科研级定理（开卷）

- 第一批（4 领域）：抽象代数（有限域生成元计数 = pⁿ − p^{n/m}）、概率论（鞅/切比雪夫）、
  复分析（Rouche/解析延拓/共形映射）、离散数学（平面图欧拉公式/编码界）
- 第二批（11 领域）：数值分析（QR 迭代/Gauss 求积/GMRES）、测度积分（Lp 对偶/Riesz）、
  微分几何（Christoffel/测地线）、统计推断（充分统计/Cramer-Rao/Neyman-Pearson）、
  常微分（Sturm-Liouville/Lyapunov）、高等代数（Jordan/不变子空间）、数学分析
  （Stone-Weierstrass/隐函数）、运筹学（最大流/匈牙利）、线性回归（正规方程/R²）、
  PDE（热方程/分离变量）、随机过程（首达时/吸收/更新方程）
- 泛函分析/拓扑学盘点确认无缺口，跳过
- **18 领域知识库达到"本科 + 竞赛 + 研究生级"三层覆盖**

### 4.4 证据闸门方向性修复

洛朗展开题实证：Python 生成代码时 SymPy 算出 -Σ（stdout 正确），但 answer 字符串写成
+Σ（符号错），代回误差 2.21 → contradict。`_evidence_override` 把"Python 自己写错符号"
误当成"Python 反驳主推理"，用 +Σ 覆盖了主推理正确的 -Σ。

**修复**：覆盖前检查 evidence_summary 是否含"验证失败/最大误差/误差/err=/FAIL"——
含则说明被验证答案代回不成立，Python 的 answer 字符串可疑，不覆盖主推理。

真机验证：修复前洛朗题 +Σ（错），修复后 -Σ（对）。

### 4.5 trace 脱敏回退（合规修正）

官方 PDF 明确：「trace 建议记录关键推理步骤、**候选答案和验证过程**，但必须脱敏，
**不写入密钥、个人信息或无关日志**」，官方示例 trace 明确记录 `content.response="候选解答"`。

之前 commit `0e4ff6c` 把"脱敏"误解为"不记录答案正文"，将候选答案/验证过程全删换成
length，方向性错误。已回退：trace 恢复记录候选答案、验证过程、选择步骤，只脱敏
密钥/隐私（本来就没有），`_truncate`/`_excerpt` 控制体积。

## 5. 深思考验证层试验（证伪后回退，重要认知）

尝试给 Python/playoff 验证层也开 thinking_mode（消除"深思考求解+浅思考验证"错配）：

- 探针：thinking_mode 下 Python 代码生成 32-43s、符号写对（laurent -= z**k）
- 真机 3 题全对，但**有限域题 python_agent 780s**（深思考对"不会验证的题"陷入超长
  思考，reasoning_content 膨胀到 max_tokens 耗尽，打穿单题软预算 840s）
- 根因：thinking_mode 只适合"有自然终点"的任务（求解/反思），不适合"可能无解/
  不会做"的生成任务（为不会验证的题写验证代码）

**结论（务必记住）**：求解层（reasoning/reflection）深思考 ✅，验证层（Python/
playoff/SymPy 代回）浅思考 prefill ✅。"验证层浅思考写错符号"的症状靠证据闸门兜底
（代回失败不信任 answer），不需要深思考除根。已彻底回退，无死分支残留。
