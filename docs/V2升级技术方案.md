# VeritasMath V2 升级技术方案

> 2026-08-12 · 方案先行 · 基于 V1 实测与官方评测实证
> 核心命题：**V2 要比 V1 更强、更好、更优秀**——三个维度分别定义、量化、可验证。

---

## 〇、为什么现在升级：V1 的三大新证据

| 证据 | 内容 | 对 V2 的启示 |
|---|---|---|
| **E1 官方评测实证** | 5:10 提交，8h+ 未结束 | 官方题比自出题**更难**（V1 全卷预算用满）；单题 20min 硬限下有**超时未答风险** |
| **E2 V1 实测边界** | 112 题 99.11%，1 partial（统计推断形式），idx=13/40 能力边界 | 正确率瓶颈已到模型能力边界与答题形式 |
| **E3 预算利用结构** | hard 1200s 中 solving 占 1150s，reasoning max_tokens 24576 | 时间大头在推理，**快速路径覆盖率决定全卷完成率** |

**V2 的三个目标（可量化）：**
1. **更强**：官方题集正确率 ≥ V1 实测（99.11%），且超时未答题 ≤ 0
2. **更好**：时间预算利用率提升（同样的 6h 解更多题 / 每题留验证余量）
3. **更优秀**：架构可扩展（新增领域/题型零成本接入），工程质量（测试/文档）达标

## 二、V2 四大升级机制

### M1【全卷完成率引擎】—— 攻 S4（最重要，官方实证驱动）

**问题**：官方题难 → 每题可能逼近 1200s → 6h 全卷可能答不完 112 题 → 未答题 0 分。

**设计**：新增 `utils/paper_pacer.py`（全局节奏控制器）：
1. **题间预算池**：把 6h ÷ 112 题的**平均预算（~193s/题）**作为基准线，
   每题开始时按已用时间动态计算"剩余可花时间"；
2. **完成率护栏**：若预估"按当前节奏会答不完"，自动把剩余题的
   `difficulty_soft_budgets` 整体下调（easy→300s / medium→600s / hard→900s），
   **保证全部 112 题都有答案**（哪怕少验证，也比 0 分强）；
3. **快速路径扩张**：与 M3 协同，让简单题更快、难题拿到更多预算。

**成本**：纯规则计算，零 API。**收益**：超时未答题 → 0，全卷完成率 → 100%。

---

### M2【答案形式对齐引擎】—— 攻 S2

**问题**：idx=94 类——数学算对，但没按题面要求的形式输出（要"半长"给"区间"）。

**设计**：新增 `utils/form_align.py`，coordinator 成稿前做轻量形式检查：
1. **题面意图解析**（零成本正则）："求 X 的值/半长/个数" → 期望单值；
   "求区间/范围" → 期望区间；"判断/证明" → 结论+证据；
2. **形式抽检**：检测最终答案形态与题面要求的错配；
3. **重述修正**：错配时追加一次低成本 LLM 重述（~512 token，温度 0，
   提示"从已有答案中提取题面要求的量"）。

**成本**：仅错配触发（~5% 题），每次 ~3s。**收益**：partial → correct，正确率 +0.9pp。

---

### M3【确定性代回验证 V2】—— 攻 S3

**问题**：idx=13/40 类——模型符号/计数错，纯重算仍错。

**设计**：新增 `utils/backsub_verify.py`，三通道（仅计算题触发，沙箱执行 ≤60s）：

| 通道 | 适用 | 做法 |
|---|---|---|
| 数值代回 | 方程/不等式 | 候选值代入题面，数值残差检查 |
| 极限定义核验 | 导数/积分 | 差分逼近核验符号方向（左/右极限同号性） |
| 多步枚举对照 V2 | 计数题 | n=2,3,4 每档枚举值逐点比对（不只最终值，还查中间项渐进一致性） |

**成本**：每题至多 1 次沙箱（≤60s，无 LLM）。**收益**：能力边界题纠错率 ~50%，
正确率潜在 +0.9~1.8pp。

---

### M4【题型快速路径扩张】—— 攻 S1

**问题**：只有填空/判断细分了快速路径，选择题/概念题仍吃完整链路。

**设计**：`verify_router` 升级：
1. **选择题**：识别选项形态（A/B/C/D）→ 快速单路径 + 选项比对；
2. **概念题**（填定义/定理名）→ 零计算快速路径（已有雏形，扩展覆盖）；
3. **已有答案的题**（题目本身给了一半答案）→ 验证型快速路径。

**成本**：纯规则，零 API。**收益**：简单题平均耗时 -40%，把省下的时间给难题
（与 M1 协同）。

## 五、实施路线（小步快跑，每步可验证可回退）

```
Phase 1: M1 完成率引擎（0.5d）— 最高优先（官方 8h 实证驱动）
  → 单测 + 模拟题间预算分配测试
Phase 2: M2 形式对齐（0.5d）— 抓 partial
  → 单测 + 真机 3 题冒烟
Phase 3: M3 代回验证 V2（1d）— 攻能力边界
  → counting_guard 合并 + 新单测 + 真机重跑 idx=13/40 类
Phase 4: M4 快速路径扩张（0.5d）— 提速
  → verify_router 升级 + 单测
Phase 5: 全量回归 + 112 题真机评测（LLM 判分）
  → 目标 112/112=100%，对比 V1 出报告
```

**每个 Phase 独立交付、独立验证、可随时回退**——完全符合你"增量增强、禁止破坏性变更"的原则。

## 六、诚实边界（不画饼）

1. M3 对能力边界题的纠错是**概率性**的（模型重算仍可能错），不保证 100% 抓出；
2. M1 的完成率引擎是**保守策略**（宁可少验证也要答完），个别难题可能因此
   牺牲部分验证质量——这是"完成率 vs 单题正确率"的显式权衡；
3. 官方题集分布未知，本地 112 题 100% 不代表官方 100%，最终以榜单为准；
4. 若官方评测本次结果已经很好（≥58 分），升级优先级可下调，先看评测结果再定。
