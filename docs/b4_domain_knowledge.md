## 0. 系统全貌（先定位）

`knowledge/` 18 个领域文件夹，每个含 `{领域}skill.md` + `{领域}验证示例.py`。加载与检索全部集中在 3 个 utils + 1 个节点：

```
classify_domain.py (节点)      → 决定加载哪一份技能文档（领域分类）
  ├─ prompt_bank.py:5-27      → CLASSIFICATION_PROMPT / CLASSIFICATION_PREFILL
  ├─ seed_prompt.py           → prefill 机制（压推理、提速 58×）
  └─ domain_loader/retrieval  → 关键词 + TF-IDF 零成本兜底

domain_loader.py     → 领域→关键词索引、技能文档/验证示例读取（带缓存）
domain_retrieval.py  → 18 领域 skill.md 摘要的 TF-IDF 字符 n-gram 索引
domain_excerpt.py    → 按"## 模块/模块速查"切块、按题面词汇打分选摘（替代位置截断）
question_profile.py  → 题型画像（计算/证明/选择/判断/填空）+ 题面结构指令（485 行）
prompt_bank.py       → 分类/推理/Python/仲裁/协调 五类提示词模板（261 行）
structured_reply.py  → 把"label = expr"字段从 LLM 答案中结构化抽取并比较（419 行）
```

**核心设计哲学（全文贯穿，来自代码注释）**：这个系统把"分类/选择"类决策做成**极快且零成本可兜底**，把省下的墙钟预算全部留给"解题"类节点——因为平台每题硬限 1200s（`config.py:60`）。所有机制都是围绕"这题值不值得花一次 LLM 往返"在做预算裁决。

## 1. 领域分类（classify_domain.py，实际 673 行）

### 1.1 分类怎么做：LLM 优先 + 确定性兜底，不是关键词限制 LLM

文件头注释（`classify_domain.py:1-11`）直接交代了演进史：**改造前**是"关键词+TF-IDF 排序出 top-3 短名单 → LLM 在短名单里选"，实测短名单经常落空，答案总是来自第二次全域调用——第一次纯属浪费约 40s。**现在**把题目直接发给 LLM、对全部 18 个领域一次分类，prefill 让模型跳过推理：约 1s、约 12 个补全 token（对比原来约 40s、约 1969 个）。关键词+TF-IDF 排序**降级为响应不可解析时的零成本确定性兜底**，不再限制 LLM 可以考虑的范围。

主流程 `classify_domain`（`classify_domain.py:629-673`）：

```
1)  stages = ["llm_prefill"]
2)  result = _classify_prefilled(...)                    # ① 快路径：prefill 单次调用
3)  if result 且 confidence ≥ 0.85（阈值）: 接受
4)  if result 有效但置信低: 仍接受（stages 记 low_confidence_accepted）
       —— 注释（651-656）：分类只是决定加载哪份技能文档，不值得花 130s 去质疑 1s 的答案
5)  if prefill 不可解析 且 时钟 fast_path(): 升级 _classify_plain（约 150s，全 CoT）
6)  全部失败 → _deterministic_fallback（关键词+TF-IDF 合并，零成本）
```

关键设计点：

- **置信度不是硬闸**：`_extract_decision`（`classify_domain.py:180-226`）先试严格 JSON，再退到 prefill 的 JSON 片段形态（种子给了 `{"category": "`，回复无法独立成对象，`classify_domain.py:205-207`），最后退到"回复中最早出现的精确域名"（`classify_domain.py:210-216`）。**缺失/不可读的置信度绝不读成 0.0**（`classify_domain.py:196-203` 注释：那会让每个有效回复都进入约 40s 的升级路径）——缺置信度时默认取阈值 0.85。
- **低置信也接受**（`classify_domain.py:652-656`）：注释记录了教训——某博弈论题低置信升级击穿节点上限，连 prefill 结果一起毁掉。分类只决定加载哪份文档，这个选择不值得花掉预算的五分之一。
- **升级的唯一合法理由**是 prefill 完全没有可解析内容（`classify_domain.py:657-667`），且 `time_budget.fast_path()` 允许。`_PLAIN_CALL_SECONDS = 150`（`classify_domain.py:258`）是实测校准值（难题上 129.5s/133.3s），`config.py:11` 的 `classifier: 200` 超时必须高于它，否则"钱花了结果被掐掉"。
- **确定性兜底**（`classify_domain.py:288-315`）：关键词候选（`find_candidate_categories`）+ TF-IDF 候选（`rank_all`）按 `1/(position+1)` 计分合并（`_merge_candidate_rankings`，`classify_domain.py:168-174`），再过滤到真实目录。兜底结果是**唯一**置信度 0.0 的分支。

### 1.2 类别名归一：五级匹配阶梯 + 官方别名表

LLM 可能吐出任何名字，而下游 `get_skill_document` 需要真实文件夹名。`_resolve_category`（`classify_domain.py:110-165`）实现严格保真的归一链：

```
官方别名表(0) → 精确(1) → 去标点归一(2) → 双向子串包含(3) → 最长公共子串≥2(4) → Levenshtein≥0.6(5) → fallback
```

- **OFFICIAL_DOMAIN_ALIASES**（`classify_domain.py:57-72`）：官方评测按 18 子领域组织题目，而 `knowledge/` 目录是另一套名字（数论/组合并入离散数学、解析几何并入非基础及进阶课程、实变函数并入测度积分、数理统计并入统计推断）。prefill 直接吐出官方领域名时先经此表落到真实目录，**避免 LCS/Levenshtein 把「数论」错配到「统计推断」**——注释明确写了"曾实测 50% 的题分类落错领域"（`classify_domain.py:52-56`）。表内容：`数论/组合/组合数学/数理逻辑/初等数论→离散数学`，`解析几何/平面几何/立体几何/欧氏几何→非基础及进阶课程`，`实变函数/实分析→测度积分`，`数理统计/统计→统计推断`，`数学建模→运筹学`。
- **LCS 优先于 Levenshtein**（`classify_domain.py:92-107`，注释：对中文类别名，编辑距离不如最长公共子串可靠；例：线性代数↔高等代数共享"代数"、概率统计↔概率论共享"概率"）。LCS 并列时再用 Levenshtein ratio 精排（`classify_domain.py:150-155`）。

### 1.3 领域硬规则覆盖层：`_domain_override`（约 270 行）

`classify_domain.py:338-607` 是一组**高精度边界规则**，命中时**覆盖 LLM 的决策**（在 `_decision_payload`，`classify_domain.py:614-626` 统一出口执行，覆盖后置信度抬到 `max(conf, 0.85)`）。规则描述的是"可复用的数学标记，而非题目编号或答案"，且宽泛词单凭自身不够、必须命中整组线索族（`classify_domain.py:338-343` 注释）。按领域列举：

| 领域 | 规则要点（文件:行号） |
|---|---|
| 数值分析 | 条件数/有限差分/有限元/截断误差/Newton-Cotes 等 20+ 记号命中即转（349-358），先于"被离散化的解析方程" |
| 线性回归 | 计量经济/异方差/内生性/工具变量/OLS/Gauss-Markov/VIF/Durbin-Watson（361-369） |
| 统计推断 | 描述统计与时间序列词（373-393）；两个组合规则：`正态分布+两个参数`、`数据+分散程度/集中趋势` |
| 偏微分方程 | 直接记号（397-400）+ 组合规则 `伴随算子 + (微分算子/∂_i/omega)`（401-407）——区分"PDE 的形式伴随"与"泛函分析的有界算子伴随" |
| 抽象代数 | Galois/分裂域/正规子群/Sylow/有限域/理想（409-416） |
| 数学分析 | 8 类记号（418-424）+ **5 个具体题面形状规则**（425-469）：圆上 Laplacian、差商函数方程、有界序列极值、五个正实数选四个、洪水/屏障/γ 增长速率博弈、Q→Z 整值函数方程 |
| 运筹学 | 直接记号（471-477）+ 2 个组合规则：`schedule+最小总成本`、`boxes+pebbles+distributes+每轮`（478-492） |
| 高等代数 | 直接记号（494-499）+ **5 个题面形状规则**（500-529）：F₂ 值函数、多项式函数方程、三元组多项式系统、m 元组配对、max-plus 元组 |
| 非基础及进阶课程 | 经典几何词（547-552）+ 4 个组合规则（多边形/三角形/线段角/平面点线圆，553-574），且**明确排除**微分几何记号（575-576：有曲率/测地线就不算这里）；注释：数三角形/六边形网格的题不会误划给离散数学 |

这套覆盖层的价值：LLM 对"竞赛题面"（尤其组合/几何/分析之间的模糊题）有系统性混淆，而规则是**可复用数学记号**，命中即可信。它是这个分类器区别于普通"LLM 分类 + 关键词兜底"方案的最大亮点之一。

### 1.4 关键词侧资产：domain_loader.py

- `DOMAIN_SYNONYMS`（`domain_loader.py:6-78`）：每个领域 8~25 个判别性关键词（中文术语 + 英文缩写），如 数值分析 收 "中心差分/Runge-Kutta/Doolittle/LU分解/finite difference"。
- `DOMAIN_EMPHASIS_TERMS` + `_domain_priority_boost`（`domain_loader.py:81-126`）：给容易判错的领域确定性加成 `100.0 + hits*5.0`——"题面带领域专属记号却缺中文关键词时，把低分小众领域排在通用代数/概率前面"。
- `_build_keywords_index`（`domain_loader.py:143-158`）：除同义词外，还从 skill.md 中收割 2~12 字符的短行（标题/要点）作为关键词。
- `find_candidate_categories`（`domain_loader.py:172-181`）计分：索引命中数 + 目录名命中 + priority boost。注释（175-177）特别说明**不要**再单算同义词命中，避免含多个同义词的领域被系统性高估。

### 1.5 检索侧资产：domain_retrieval.py（69 行）

- 对每份 skill.md 提取"标题 + 各级小标题 + 短行（核心概念）"摘要，上限 1500 字符（`domain_retrieval.py:18-36`）。
- `TfidfVectorizer(analyzer="char_wb", ngram_range=(2,4))`（`domain_retrieval.py:43`）——字符级 2-4 gram 免分词处理中文。`rank_all` 对题面算余弦相似度排 18 类；`rerank` 对候选重排。
- 接口注释（`domain_retrieval.py:1-5`）：以后接 embedding API 只需替换 `encode()/_build()`。

## 3. 检索机制：怎么选内容注入 prompt

### 3.1 两级加载：分类定领域 → 摘录定片段

1. 分类节点产出 `category`（严格 ∈ 真实文件夹名）→ 下游节点 `sl.get_skill_document(category)` / `sl.get_validation_script(category)`，**带内存缓存**（`domain_loader.py:160-170`）。
2. 每份文档**不整体注入**，按题面主题选摘（见 3.2）。四个摘录预算点：

| 使用点 | 预算 | 位置 |
|---|---|---|
| 推理主分支 skill 摘录 | 3000 字符 | `reason_step.py:410` |
| 客观题快速路径 skill 摘录 | 2200 字符 | `reason_step.py:487` |
| Python 验证分支验证示例摘录 | 2000 字符 | `verify_step.py:220` |
| Python 验证分支 skill 补充摘录 | 1600 字符 | `verify_step.py:229` |

### 3.2 select_skill_excerpt：按模块打分选摘，替代位置截断（domain_excerpt.py:132-208）

动机注释（`domain_excerpt.py:1-13`）是**真实事故复盘**：`skill_document[:3000]` 是位置性截断——文档比上限长时无论题目问什么，都只给开头模块；当"非基础及进阶课程"长到 8.9k 字符时，数论/博弈论模块落在偏移 3404-8949，整个超出 3000 窗口，**一道博弈题拿到的是 Lebesgue 测度与泛函分析模块，真正为它写的内容一个字都没进**。

机制（`_select`，`domain_excerpt.py:141-208`）：
1. 按 `_MODULE_RE`（`^##\s*(?:模块|\d+\s*[.)、:：-])`，:21）把文档切成 前言 + 模块列表；无模块结构 → 退回 `text[:limit]`（:149-150，**无痛替换裸切片**）。

4. 分配预算（:165-208）：**得分最高的模块先拿预算**（注释：按文档序贪心会塞进两个不相关小模块、却给真正对口的模块留不出空间——这正是整套机制要防的失败），仅榜首允许截断（:179-184，次名截断会剪掉条目尾部的收尾配方）；随后按排名贪心填充可整条放下的模块。**前言始终保留**（领域边界/路由约定是每道题都需要的）。前言超预算时头部封顶 `min(limit//2, 1200)` + 命中的速查模块平分（:170-188）。
5. `跨学科/通用/附录` 小节 +1 分（:161-163），与其他模块同场竞争。

## 4. 题型画像（question_profile.py，实际 485 行）

### 4.1 题型判定：五类 + 严格优先级

`classify_question_mode`（`question_profile.py:73-101`），优先级**刻意排列**（注释 :74-91 每一条都是事故教训）：

```
判断(true_false) → 强证明信号(proof) → 选择题(choice) → 填空(fill) → 证明(proof) → 计算(computation)
```

- **判断题最先**（:83）：选择题干可能含"判断下列命题"。
- **强证明信号第二**（:88，`_STRONG_PROOF_RE` :47-52）：`show/prove/demonstrate/establish/justify/verify/derive + that|the|for|any|...`、`证明/求证/试证/论证/说明理由/辐角原理/留数定理/laurent expansion`。注释（:44-46）记录事故：复分析题用 (A)(B) 标注假设条件、被选项检测误判成 choice，模型答了个 "A"。
- **选项检测**（:92-94）：`_OPTION_RE`/`_OPTION_PAREN_RE`（:26-27）支持"选项内嵌题干"（`A.均值B.方差`），计数 ≥2 或出现"选择题/单选/多选"即 choice；**必须先于通用空位标记**，否则每道客观题都被判成填空（:91）。
- `mode_from_metadata`（:55-70）：优先采纳接入方下发的 `question_mode/type/question_type/problem_type`，但不变成运行时依赖。
- 题型集合：`KNOWN_MODES = {proof, computation, choice, true_false, fill}`；`CLOSED_MODES = {choice, true_false, fill}`（客观题，:14-15）。

### 4.2 识别后的使用（贯穿全图）

- **输入阶段**定档：`agent_state.py:66`（`mode_from_metadata(...) or classify_question_mode(problem)`）→ `state.question_mode`。
- **扇出裁剪**：`graph/solve_branch.py:18-21`——客观题只扇出推理分支，**不再并行 Python 分支**（省一次昂贵 LLM+代码往返）。
- **推理快速路径**：`reason_step.py:417-509`——客观题用 `objective_reasoning` 温度 0.2、max_tokens 4096、两行契约（`答案：<...>` 在 `依据：<...>` 前，:474-480）；`needs_derivation` 正则（:463-466，分裂域/扩张次数/维数/秩/阶/特征值/收敛半径）命中时切换"先算后答"三行契约（:467-473）——注释（:459-462）：对需要实算的客观题，"先承诺后核对"顺序恰好是反的，曾出现先写下 `Q(∜5,i);8` 再补依据。
- **Python 分支跳过**：`verify_step.py:190-210`——客观题不生成程序（"选择/判断/填空由短推理路径作答；生成 Python 只会增加延迟，且常产生无法表达多个选项字母或空位的误导性标量"）。
- **交叉验证侧**：`judge_step.py:31-70`——客观题不走 `AnswerCompare`，直接归一化答案并打固定置信 0.78（填空分项不足时降到 0.45，:47）。
- **提示词注入**：`mode_instruction`（:228-266）给每个题型附加输出契约——choice："先判断单选/多选，按教材严格措辞逐项核对，宁缺勿滥，最多 3 个短步骤"；true_false："先给正确/错误，再用反例或定理说明"；fill："按空位顺序逐项作答，格式 `空1: <结果>；空2: <结果>`，禁止'不确定'，不要把同义解释拆成多空"；proof："至少两步蕴含链 + 检查边界/等号条件"；computation："列出全部量、逐项标注，中间量不能代替最终结论"。

### 5.2 "答案前置"种子（本任务点名要查的机制）

REASONING_PROMPT（:29-95）的骨架：

```
"## 结论速览" 必须放在最前        :32
\boxed{[最终结论的一句话压缩版]}   :63   ← 答案前置
## 问题分析 / 详细解题步骤 / 最终答案 / 关键验证点   :65-84
"## 最终答案" 与 "## 结论速览" 必须完全一致          :58-63
```

即**先让模型在推导前把最终结论以 \boxed 形式写死在开头**，后面四节展开，最终答案必须与速览一致——把"承诺"放在"推导"之前，防"推导跑完结论跑偏/占位符/漏分支"。同一模式出现在：客观题两行契约（`答案：` 行在 `依据：` 行前，reason_step.py:474-480）、协调器（`最终答案` 章节镜像 `validated_answer`，prompt_bank.py:150-152,168）。**prefill 是另一层"种子"**：`seed_prompt.py:28-30` 在助手回合种下 `{"category": "` 或 `ARBITER_{nonce}=`，把模型带进续写模式、不开 `reasoning_content` 块；`stitch`（:33-55）兼容三种后端行为（续写/回显/忽略）。实测数据（seed_prompt.py:5-8）：分类 40.4s→0.9s（1969→12 token，58×）、仲裁 70.2s→0.8s（4 token，140×），精度无损（分类 4/4、仲裁 3/3 含对抗样本）；对比方案"截断 max_tokens"在 64/128/256/512 各上限下 11 次探针全部只返回残缺 `Thinking Process:`（:14-17）。

### 5.3 推理提示里的"口径检查清单"（REASONING_PROMPT :38-50）

逐字读题/开区间优先/自然数含 0（计数题 n=0 恒满足时按含 0 给主值）/端点可达性（临界值回代，取不到则 +1）/序号对齐/对称因子只乘一次（闭式含规模因子时先用最小非平凡实例标定口径）/不可能性先证伪/值域即代数结构/单双尾事件/算子作用空间（Laplace–Beltrami）/答案类型与问法一致/最简形式。这些是**泛化到所有题的口径规则**，与 §4.3 的题面结构指令互补：一个看题型、一个看语义。

## 6. 结构化回复（structured_reply.py，实际 419 行）

### 6.1 extract_named_fields：从 LLM 答案里抽 "label = expr" 字段

管线（:256-309）：按 `;；\n` 在**数学定界符之外**切段（`_split_outside_math`，:114-150，支持 `$$`/`\[..\]`/`\(..\)`/`$`，:11）→ 段内抽数学跨度（`_math_spans`，:153-179）→ 对含 `=` 的跨度做 `_parse_assignment`（:227-242：顶层唯一 `=` + 标签白名单 + 表达式长度 ≤400）→ `_canonical_label` 归一标签（:87-102：`\bar{y}`→`y`、`\beta_0`→`beta0`、`最大值`→`maximum`——注释：`\bar y` 与裸 `y` 曾对不上）。

约束：`MAX_ANSWER_LENGTH=4000`、`MAX_FIELDS=16`、`MAX_EXPRESSION_LENGTH=400`（:8-10）；输出 `ExtractedFields(fields, assignment_like_count, unconsumed_segments, malformed_delimiters)`。**`unconsumed` 与 `malformed` 是关键的"不可用"信号**——普通散文 `f(x)=x^2` 解析不出赋值式，会进入 unconsumed，阻止假的一致判定。

### 6.2 两个高层判定

- `is_self_conflicting`（:312-329）：同一答案给同一字段赋两个不等价的值 → 自身矛盾（注释：`a=1; a=2` 自身就错，所以两份一致副本彼此同意不构成证据，:318-321）。`malformed_delimiters` 直接判 True（截断/不平衡定界符视为不可用）。
- `compare_structured_answers`（:332-419）：左右两份答案逐字段用调用方注入的 `equivalent`（符号比较函数）对比。判定规则（:345-408）：
  - 不适用（无赋值、无残留、无畸形）→ `applicable=False`；
  - 有残留/畸形 → `verdict=None`（**不判错，判不可判定**——防把解析失败当矛盾）；
  - 有字段冲突 → `False`；字段集不同或不完整（<2 个字段）→ `None`；存在不可比字段 → `None`；全部等价 → `True`。
  - 产出 `coverage = matched/union`、`matched/mismatched_fields` 明细。
- 消费方：`answer_compare.py`（推理散文 vs Python 输出做 `structured_symbolic` 级比较）——这是"字段完整性契约"的执行侧：REASONING_PROMPT :36、PYTHON_PROMPT :244、COORDINATOR_PROMPT :159 都要求统计题保留命名字段（标准误/SSE/自由度/ANOVA 表），structured_reply 负责验证这些字段是否真的存活且等价。`LABEL_ASSIGNMENT_PREFIX_RE`（:80-84）导出给表达式解析器复用同一套标签规则，避免两套规则悄悄不一致。

## 7. 亮点清单（按对 71 分贡献排序）

1. **prefill 分类 + prefill 仲裁**（seed_prompt.py 全篇、prompt_bank.py:27,214）：把 40s/70s 的"选择类"调用压到 ~1s，且精度无损。**这是所有机制里杠杆最大的一根**——平台每题 1200s 硬限（config.py:60），省下的时间全变成解题节点的预算。配套认知：prefill 压掉的是私有推理不是指令（prompt_bank.py:173-174 注释），规则必须保持显式。
2. **领域硬规则覆盖层 `_domain_override`**（classify_domain.py:338-607）+ **官方别名表**（:57-72）：修复 LLM 对竞赛题面的系统性错配（"数论"错配到"统计推断"曾达 50%）。规则全部是**可复用数学记号 + 线索组组合**，不是题目编号——这决定了它可迁移、可维护。
3. **模块级知识摘录 `select_skill_excerpt`**（domain_excerpt.py:132-208）：修复位置截断事故（博弈题拿到 Lebesgue 测度）；`检索词：` 显式行 + `_TOPIC_CUES` 线索映射 + 标题双倍权重 + 前言常驻 + 榜首优先贪心——把"文档>3000 字符时模型看哪段"从偶然变成工程。
4. **题型画像 + 题面结构指令**（question_profile.py）：客观题裁剪扇出省一整条 Python 分支；`structure_instruction` 的七条检查单**逐条对应真实丢分事故**（F₂ 求和、端点可达、序号对齐、全部解、不可能性证伪、空位数）。这是"从错题里长出来的提示词工程"，成本极低、命中即得分。
5. **"答案前置" + 结论速览**（prompt_bank.py:32,58-63；reason_step.py:474-480）：推导前先承诺 \boxed 结论，最终答案必须与速览一致——对抗占位符/跑偏/漏分支。配合 `answer_coverage_clause`（question_profile.py:335-355）保证压缩重试不漏答案分支。
6. **置信度/预算哲学**（classify_domain.py:196-203,651-656；config.py:15）：分类低置信**不升级**（只是选文档，不值得花 130s）；缺失置信度读成阈值而非 0.0；升级的唯一理由是"完全无解析内容"。每一条都是对"把预算花在刀刃上"的量化执行。
7. **验证示例双注入**（reason_step.py:404-413 + verify_step.py:214-231）：推理节点读 skill.md（怎么建模/算什么），Python 节点读验证示例（怎么写核验代码），且都按主题摘录；验证示例是"提示文档不是程序"，代码片段带占位符和反例警示（数学分析验证示例.py:3,77）。
8. **结构化字段抽取与比较**（structured_reply.py）：让"字段级一致性"可机械判定（`\bar y`≡`y`、`最大值`≡`max v`），统计题命名字段（标准误/SSE/ANOVA）必须存活；`unconsumed/malformed → None 不判错`的保守策略避免解析失败被误当矛盾。
9. **推理提示的口径检查清单**（prompt_bank.py:38-50）：开区间优先/自然数含 0/对称因子只乘一次/值域即代数结构——泛化到所有题的高价值低代价规则，与知识库内容互补。
10. **语义仲裁器**（prompt_bank.py:175-214）：只选不答 + nonce 防回放 + 执行证据真实性规则（"打印 popcount 自称 computed"判无关），prefill 后 0.8s/4 token；是"Python 验证与推理冲突"时的最终裁决层。
11. **确定性兜底链**（classify_domain.py:288-315 + domain_loader/domain_retrieval）：关键词 + TF-IDF（char_wb 2-4 gram 免分词）合并排序，惰性构建、正常路径从不运行（:290-292）——鲁棒性零成本。
12. **question_anchor**（question_anchor.py 全篇）：题目 SHA-256 快照锚定，重试分支不被中间改动污染（:28-54）。

## 8. 与我们项目（skills_pythonscripts）的对比

### 8.1 关键事实：同源，但各自分化

- **同源证据**：我们 `skills_pythonscripts/` 与对方 `knowledge/` 是**同一 18 领域布局、同一文件命名**；18 份 `验证示例.py` **逐字节相同**（MD5 全等：identical=18/18）；`skills_loader.py` ≈ `domain_loader.py`（同义词表几乎一致）、`skill_excerpt.py` ≈ `domain_excerpt.py`（同正则、同线索表、**连事故注释都相同**）、`classifier_node.py` ≈ `classify_domain.py`、`problem_profile.py` ≈ `question_profile.py`、`structured_answer.py` ≈ `structured_reply.py`、`prompt_templates.py` ≈ `prompt_bank.py`。我们是从同一母版演化的后续版本。
- **skill.md 全部不同**（identical=0/18）：我们总字符 ≈507.6k vs 对方 ≈497.4k，总量相当，但分布相反：

| 领域 | 对方字符 | 我们字符 | 差距 |
|---|---|---|---|
| 离散数学 | 87,689 | 60,685 | **对方多 27k（竞赛速查条目为主）** |
| 非基础及进阶课程 | 56,070 | 45,867 | 对方多 10k（含完整例题解） |
| 概率论 | 28,272 | 33,249 | 我们多 5k |
| 复分析 | 37,976 | 43,234 | 我们多 5k |
| 随机过程 | 38,470 | 42,268 | 我们多 4k |
| 其余 13 域 | — | — | 互有增减（偏微分方程/测度积分/常微分方程等我们更大） |

### 8.2 对方领先、应直接移植的三点

1. **`OFFICIAL_DOMAIN_ALIASES` 官方别名表**（classify_domain.py:57-72）：**我们完全没有**（grep 全仓无此表，我们的 `_resolve_category` 只有五级阶梯、无第 0 级别名步）。官方评测按 18 子领域命名题目，prefill 直接吐"数论/解析几何/实变函数/数理统计"时，我们的 LCS 阶梯会把「数论」错配到「离散数学」之外的可能目录（对方注释：错配率曾 50%）。**这是最该抄的一行表。**
2. **竞赛速查条目（`## 模块速查：` + `- 检索词：`）**：对方离散数学 56 条、非基础及进阶课程 54 条、数学分析 17 条显式检索行，我们对应文档的检索行数明显更少（我方文档总字符虽大，但速查条目结构是否齐全需自查——对方在"最竞赛"的两个领域上投入最多）。速查条目直接对接摘录机制（domain_excerpt.py:63-89 的 `_RETRIEVAL_LINE_RE` 就是为它写的），是"题库模式 → 知识库 → 检索"闭环的关键载体。
3. **`_domain_override` 的线索组写法**：我们有同名函数（classifier_node.py:317），但对方对 数学分析/高等代数/离散数学 的**具体题面形状规则**（如"五个互不相同的正实数+选取四个+最小值"、`f:Q→F₂`、`g(bx-a)`）更细——这些是对方从评测数据逐题挖出来的，建议逐条对照补齐。

### 8.3 我们领先、应保持的资产

- **分类器额外产出难度画像**（`_DIFFICULTY_RE`/`_extract_difficulty`，classifier_node.py:139-146，VeritasMath 用）——对方没有。
- **额外机制节点**：`DIVERSE_METHOD_HINT`（第二独立解法）、CRITIC（答案审计）、PLAYOFF（冲突裁决）、`deep_solver`、`is_property_judge`（判断题面属性判定，problem_profile.py:114）——对方 prompt_bank 只有 分类/推理/协调/仲裁/Python 五类模板。
- **客观题契约的 `needs_derivation` 先算后答开关**（reason_step.py:463-473）双方都有，属同源。

### 8.4 结论

知识库资产（验证示例）完全同源、skill.md 总量相当，**真正的差距不在"有多少字"，而在三处**：① 官方别名表（防 50% 错配）；② 竞赛领域（离散数学/非基础）的速查条目密度与检索行；③ `_domain_override` 的题面形状规则细度。这三项都是"低代码成本、直接命中官方评测题"的移植项，建议按 ①→③→② 的顺序吸收；同时保留我们已有的难度画像与 CRITIC/PLAYOFF 等增量机制。
