## 三、V2.6：深度反思环 + 判分器对齐（第二批）

### 3.1 深度反思环（核心）

`retry_count=0` 揭示的根因：reasoning+python 两路"match 一致"就直达 coordinator
出厂——即使两路**一致地错**（单样本系统性错误），也没有任何环节回答"答案到底
对不对"。Critic 只审"完整性/缺项"，从不审"正确性"。

新增 `nodes/reflection_node.py`，挂在 Critic 后：

```
solving → critic → reflection → coordinator
                        │
                        ├─ 确认正确 → 放行
                        └─ 发现实质错误 → 定向修复提示 → reconciliation 重算
```

- **反思什么**：代回验证、差一/序号、符号/量纲/值域、边界/退化、最优性/反例
- **触发条件**：所有非客观题反思一次（不依赖分类器 difficulty/confidence——
  实测分类器把 L4 科研级题判 easy + 0.98 高置信却照样答错，信号不可靠）
- **判定纪律**：只有"实质错误证据"才判 wrong，宁可放行不误杀
- **兜底**：反思失败/超时/预算不足一律放行，不阻塞主链路
- **合规**：定向纠错（复用 reconciliation 既有重算回路），非简单 rollout

### 3.2 token 摆脱分类器

真机发现分类器把 L4 科研级题判 easy + 0.98 高置信，而模型在这些题上照样答错。
easy 档 8192 会让"被判 easy 的难题"答案被截断（truncated 的根因之一）。
easy 提到 16384 与 medium 平齐——max_tokens 是上限非配额，提高不增加耗时。

### 3.3 判分器对齐官方口径

`grade_llm.py` 判分 prompt 从"只要答案等价即 correct"改为"判答案 + 过程合理性"
（对齐官方"结合参考答案与解题过程综合判定"）。

### 3.4 fix_hint 去锚定

反思 LLM 与主模型同源会误判（idx=28：反思说"应为 198"实际 748）。剥离 fix_hint
里"应为 X"数值锚定，只保留错误性质，让重算独立推理，防误判把对的改错。

## 四、真机验证（v26 纯 L4 科研级 112 题）

### 4.1 题集

- 112 题，L3 22 + L4 90（科研级占 80%，比 v25 更难）
- 18 领域分布严格对齐官方
- 陌生应用 + 数值实例（避免教科书原题）

### 4.2 结果

| 指标 | 数据 |
|------|------|
| 表面正确率 | 84.8%（95/112） |
| 剔除 13 题 API 流控后 | **95.96%（95/99）** |
| 反思环触发率 | 96%（108/112） |

17 个 wrong 里：13 题是 API 400 流控失败（elapsed 2.7-4.4s，与 v25 的 11 题同因，
本地环境工程失真，官方 0 error 不受影响）；真正模型错的只有 3 题（过程错、多问漏答、
答非所问），全是模型能力边界/题面理解，机制难修。

### 4.3 反思环行为分析

- 87 题判 correct 放行、1 题判 wrong（idx=28，误判——反思说 198 实际 748）、
  20 题 skipped/pass、4 题客观题未触发
- **结论**：反思环机制稳健（fix_hint 是提示非指令，误判不把对的改错），但本地题
  模型首轮答对率 ~97%，反思环"救回"价值趋近于零。真正价值需官方实测。

## 五、三连证伪（重要认知，勿再重蹈）

本地五套题集 + 三种判分口径，均无法复现官方 59.8% 落差：

| 假设 | 验证方法 | 结果 |
|------|---------|------|
| 题集太简单 | 换陌生应用题集（v25）、纯 L4 科研级（v26） | 96-97% ≈ 98%，证伪 |
| 过程缺失 | 判分器加"判过程"口径 | 只掉 1 题，证伪 |
| 判分口径太松 | 判分器对齐官方"判过程" | 只掉 1 题，证伪 |

**结论**：本地题模型确实会做（~96%），官方 59.8% 的落差根因在官方黑盒（官方
judger 具体实现 + 官方题集具体内容），本地无法复现。
