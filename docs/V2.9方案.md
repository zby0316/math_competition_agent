# V2.9 改进方案：修复 thinking_mode 截断 + 控制墙钟

> 2026-08-17 · 基于 V2.8 官方实测 58.04 分（65 correct）的硬数据驱动

## 1. 背景：V2.8 官方实测的硬数据

```

request_count: 1084, retry_count: 0
truncated_count: 366（33.8%！之前 V2.4/V2.6 是 112 = 10.2%）
completion_tokens: 平均 3050/请求
墙钟: 5h（逼近 6h 上限，之前 V2.4 是 2.5h）
```

### 分数轨迹

```
V1:   60 correct = 53.53 / truncated ?
V2.4第一次: 67 correct = 59.82 / truncated 91  ← 历史最高
V2.6: 60 correct = 53.57 / truncated 112
V2.8: 65 correct = 58.04 / truncated 366  ← 本次
```

## 2. 核心矛盾：thinking_mode 是一把双刃剑

| 维度 | V2.6（prefill 抑制思考） | V2.8（全量 thinking_mode） |
|------|------------------------|--------------------------|
| correct | 60 | **65（+5 题）** ✅ |
| truncated | 112（10.2%） | **366（33.8%）** ❌ 暴涨 3.3 倍 |
| 墙钟 | 2.5h | **5h** ❌ 逼近 6h |

**结论**：thinking_mode 提分是真实的（+5 题），但代价是截断暴涨 3 倍 + 墙钟翻倍。
**若截断的 366 个答案能写完，correct 很可能到 70+** —— 这是当前最大提分空间。

## 3. 根因分析（三个确定性缺陷）

### 缺陷 1：thinking_mode 全量开，easy 题也被迫深度思考

当前 `enable_thinking_mode: True` 对所有难度统一生效。easy 题（简单计算题）本来
prefill 就能答对，却被强制深度思考——思考（reasoning_content）挤占 max_tokens，
答案（content）空间被压缩 → 截断。这是 truncated 从 112→366 的主因。

### 缺陷 2：反思环 thinking_mode 的 content 混入思考文本（探针定位的精确根因）

探针验证（thinking_mode + max_tokens 对比）发现反思环**必截断**：reasoning_content
= 0 字符，content 却 3394-6816 字符且开头是英文思考 "We need to evaluate..."。
反思环的 prompt（system + 判对错 JSON）在 thinking_mode 下，模型不产生独立
reasoning_content，而是把"英文思考 + JSON"全塞进 content → max_tokens 不够 →
finish=length 截断。这是 V2.8 truncated=366 的主力（反思环 ~100 题 × 截断）。

### 缺陷 3：主推理 thinking_mode 不截断（探针证实，无需改动）

探针验证：主推理（有限域/简单计算/证明）thinking_mode 下 reasoning_content 与
content 正常分离（2541/614 字符），finish=stop 不截断。所以 truncated 的主力
是"反思环 content 混思考"和"easy 题 thinking_mode"，不是"max_tokens 不够"——
这也解释了 V2.7 token 上调没降 truncated。

## 4. 改进方案（三个动作）

### 动作 1：分级思考（核心，解决截断 + 墙钟）

| 难度 | 方式 | 理由 |
|------|------|------|
| **easy** | prefill 直答（不开 thinking_mode） | 简单题不需要深度思考，prefill 快且不截断 |
| **medium** | thinking_mode + max_tokens 32768 | 需要思考，但 token 给足 |
| **hard** | thinking_mode + max_tokens 32768 | 科研级题最需要深度思考 |

- 预期：easy 题（约 1/3）不思考 → 截断减半 + 单题耗时减半
- 保留：medium/hard 题的深度思考（V2.8 提分的主要来源）

### 动作 2：关闭反思环 LLM 反思，只保留 SymPy 代回

- **关闭** `enable_reflection_thinking`（LLM 反思深度思考，retry=0 证明无效）
- **保留** SymPy 代回硬验证（V2.7 加的真机有效：抓差一/错值，确定性判定）
- 预期：省 ~2h 墙钟（反思环 112 题 × 70s）+ 省 ~112 次深度思考调用的 token
- 风险：极低——retry=0 证明 LLM 反思本来就"永远放行"，关闭不损失任何重算

### 动作 3：thinking_mode 题的 max_tokens 精准化

- medium/hard 的 max_tokens 统一到 32768（给足，覆盖思考 + 长答案）
- easy 用 prefill 后 max_tokens 可降回 8192（prefill 抑制思考，token 只花答案）

## 5. 预期收益

| 指标 | 当前（V2.8） | 预期（V2.9） | 依据 |
|------|-------------|-------------|------|
| truncated | 366（33.8%） | ~150（~14%） | easy 不思考 + 反思不思考 |
| 墙钟 | 5h | ~3h | 省反思环 2h + easy 提速 |
| correct | 65 | **70+** | 截断的题答案写完 |
| 分数 | 58.04 | **63-68 分** | 超历史最高 59.82 |

## 6. 实施步骤

1. config.py：加 `thinking_by_difficulty` 配置（easy=False/medium=True/hard=True）
2. reasoning_agent_node：按难度选择 thinking_mode 还是 prefill
3. config.py：`enable_reflection_thinking: False`（保留 SymPy 代回）
4. 真机验证：跑 10 题 L3/L4，对比正确率 + 单题耗时 + truncated 变化
5. 提交官方评测

## 7. 诚实边界

- 分级思考是"工程优化"，能解决截断 + 墙钟，但**不能保证**超 59.82（题集波动 ±6 分）
- thinking_mode 的提分（+5 题）是真实的，本方案是"保留提分 + 消除副作用"
- 最终分数仍取决于官方题集（本次 input_sha256=7f2499c5，与 V2.4 不同题集）
