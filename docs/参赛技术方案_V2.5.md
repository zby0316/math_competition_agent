# VeritasMath：多径推理与确定性校验数学智能体

## —— 基于 Intern-S 系列模型的数学智能体设计与推理创新 · 参赛技术方案（V2.6.2）

> 题目编号 XH-202627 | 发榜单位：上海人工智能实验室

---

## 摘要

VeritasMath 是一个面向研究生级数学竞赛题的推理智能体，核心设计思想是：**在"锁单一模型 + 纯 API 调用 + 20 分钟单题硬限"的强约束下，用"多候选生成 + 确定性校验 + 过程审计"的架构，把模型能力内的正确率榨干到上限**。

官方评测（同题集 7f2499c5）轨迹：V1 53.53 分 → V2.4 **59.82 分（67/112）** → V2.9 53.57 分（多候选采样反噬）→ **V2.5 61.61 分（69/112，历史最佳）**。V2.6/V2.6.1/V2.6.2 在 V2.5 之上完成：截断续写雪球治理、sympy 自然语言化、单候选代回核验（对标榜一"sympy 硬校验"）、全代码审查的四类漏括号 bug 修复与官方领域分布配置对齐，并建立 16 题困难题校准集（真机 16/16 全对）作为每轮改版的相对验证闭环。

**一句话核心**：不是让模型"更努力地想"（思考模式实测反噬），而是让模型"在会做的题上绝不因架构而做错"。

## 一、任务理解与判分机制分析

### 1.1 任务

实现 `agent.solve(problem: str, metadata: dict) -> dict`，返回含非空 `final_response` 的可 JSON 序列化字典。平台注入官方 client，只经 `client.chat(messages, temperature, max_tokens)` 组织请求。

### 1.2 三条决定性事实（决定全部设计）

1. **评分完全客观**：初赛按判分系统榜单排名客观评分（官方知识库 2026-07 明示），
   无 partial 分公式公布、无逐题反馈；官方 judger 为 Intern-S 模型语义判分。
2. **judger 判"结论 + 过程合理性"，不是字符串匹配**。LaTeX 等价表达判对
   （-1/8 与 -1/8 分数形式一致），但证明/推导题"答案对而过程缺失"只给部分分。
3. **硬约束**：单题 20 分钟、全卷 6 小时墙钟、并发 3、慢 API 下私有 CoT 生成极慢
   （16384 token ≈ 811s）、禁联网/外部 API/Lean4、SymPy + 离线 RAG 允许、
   每天仅 2 次提交（12:00/24:00 批次）、每周 10 次。

### 1.3 历史评测的硬教训（V2.6.2 的设计依据）

同题集（7f2499c5）官方实测，correct / truncated / 墙钟：

| 版本 | 策略 | correct | truncated | 墙钟 |
|------|------|---------|-----------|------|
| V2.4 | prefill 直答（不思考） | 67 | 91 (10%) | 2.5h |
| V2.5 | prefill + sympy 短路 + 续写 | **69** | 203 (14.5%) | 3.9h |
| V2.8 | thinking 深度思考 | 65 | 366 (33.8%) | 5h |
| V2.9 | 思考 + 多候选采样 N≥8 | 60 | 302 (19%) | 6.8h |

**结论**：在慢 API 下，"思考模式"和"大 N 采样"都会让 CoT 塞满 max_tokens → 答案
截断 → 正确率反跌。**最优策略是 prefill 抑制 CoT（答案短、不截断）**，这正是
V2.4/V2.5 拿最高分的根因；V2.5 的 203 截断来自续写循环雪球，V2.6 已治理
（续写轮数 2→1 + token 分级），V2.6.1 进一步修复截断启发式误判。

## 二、系统架构

### 2.1 三层提分架构

```
求解生成层          →   验证仲裁层           →   知识底座层
─────────────────────────────────────────────────────────
M2 prefill 直答         M5 三路交叉验证         M8 定理离线 RAG
M3 异构 B 路径          M4 SymPy 确定性校验     (18 子领域研究生级定理)
M15 单候选代回核验      M6 过程审计 Critic       M9 流控预算护栏
(substitute 第三证据)   M7 反思纠错             M16 单题请求硬上限
                        M10 成稿格式化交付
```

数据流：`题面 → 分类(题型×领域) → 双路求解(A prefill直答 + B 异构 + Python) → 三路交叉验证 → match 后单候选代回核验/冲突时确定性裁决 → 过程审计 → 成稿(含必要过程)`。

### 2.2 编排

LangGraph 状态图，12 个模块（节点）协同，共享 state 字典。每节点有独立的时间/预算护栏，单题最坏路径受 20 分钟硬限约束；每问题 LLM 调用总数另有硬上限（默认 24，emergency 豁免），任何路径失控都会快失败走确定性兜底。

## 三、核心机制（六大创新，对应主观分"创新性"维度）

### 机制一：prefill 抑制 CoT（确定性提速，不思考直答）

用 assistant 种子（`## 问题分析\n`）接管助手轮，让模型跳过私有推理链（reasoning_content）直接作答。**思考引导由提示词内化七点承担**（结构/覆盖/逻辑/自洽验证），不依赖不可控的 CoT 空想。

**为什么有效**：慢 API 下 CoT 计入 max_tokens 且生成极慢（811s/题），是截断和超时的元凶。prefill 直答答案短、快、不截断——**同题集实测：不思考 67 题 > 思考 65 题 > 采样 60 题**。

### 机制二：异构双方法推理 + 三路投票（打破同源一致地错）

A 路径（prefill 直答）与 Python 路径（SymPy 代码求解）**同源**（都是 S2），可能"一致地错"。B 路径用**异构方法提示**（DIVERSE_METHOD_HINT）强制换解法，提供方法论独立的第二证据。

三路投票的关键修复：**A=Python 一致时，若 B 反对，触发确定性裁决 A vs B（异构），而非放行"同源一致地错"**。这是纯字符串比对，零 token 成本。

### 机制三：确定性复算季后赛 Playoff（从"只能选"到"先算清楚再选"）

候选冲突时，不解原题，只做**候选代回核验**：方程回代看残差、极值比较目标函数实测值、计数缩小规模枚举对照、存在性实际搜索构造。产出的是**确定性证据**而非又一次采样判断。

**为什么有效**：语义仲裁只能从既有候选中选——两个都错时必输。Playoff 用确定性计算戳破"假一致"和"假反驳"。

### 机制四：SymPy 确定性校验（防止"答案对但过程错"）

judger 判"结论 + 过程"，答案对但中间步骤错也会判错。VeritasMath 用 SymPy 做确定性校验：候选答案代回题设条件验证、符号复核、assert 自调试——用确定性计算锚定过程正确性，而非依赖模型自报。

### 机制五：证据闸门（正确答案不被 Python 错答案覆盖）

Python 代回发现矛盾（FAIL/反例）时，**不得**用 Python 的错答案覆盖仲裁选定的正确答案。证据闸门拦截"Python 自报证据 ≠ 真实反驳"的情况，同时尊重 Playoff 的确定性裁决优先。

### 机制六：定理离线 RAG（开卷查定理，而非闭卷空想）

官方 18 个子领域（离散 24/数值 13/测度 11/微分几何 9 占一半分值）的研究生级定理，按"检索词 + 定理精确陈述 + 解题路线 + 易错点 + 分步算例"的模块速查格式注入提示词。让模型面对研究生级题（Sylow、Galois、留数、Rouché、CLT 等）时"开卷"而非空想。

### 机制七：单候选代回核验 Substitute（V2.6.1，对标榜一"sympy 硬校验"）

三路投票与季后赛都只防御"两路**不一致**"；当推理与 Python 两路**同源一致地错**时（同一模型、同一题面读法），没有任何机制拦截。Substitute 提供第三种证据：medium/hard 计算题 match 后，把两路一致的候选答案**代回题面条件**做确定性核验——方程验残差、极值代回比较、计数小规模枚举对照、数值题独立重算。PASS 才进过程审计；FAIL（被确定性计算证伪）带定向提示回调解重算；证明/概念题无法机械核验时良性放行。

**为什么有效**：这是"两路同错"这一最后盲区的确定性补丁——代价仅一次 prefill 代码生成 + 沙箱执行，且预算不足时自动跳过、不阻塞出答案。

## 四、消融实验（有效性证据，对应"创新性"维度的硬要求）

同一道题、同一模型、开关机制前后的真实对比：

| 机制 | 消融证据 |
|------|---------|
| 异构 B 路径 | 洛朗展开 `-z⁷`（错）→ `-1/z-Σ`（对） |
| 证据闸门关键词 | 洛朗 `-z⁵`（错）→ `-1/z-Σ`（对） |
| 三路投票 | 堵住"同源一致放行"，B 反对触发裁决 |
| 定理 RAG | 有限域 F₆₄ 生成元 54（容斥，旧公式会得错 56） |
| prefill 直答 | 同题集 67 题（不思考）> 65 题（思考）> 60 题（采样） |
| 单候选代回核验 | 真机：match 后 medium/hard 计算题进 substitute 核验，PASS 放行 / FAIL 触发定向重算（16 题校准集全对且 idx=1 同余题 sympy 短路 0 次 LLM 推理） |
| sympy 短路守卫 | 真机：lerchphi 未定值垃圾与"梯形近似题被算成精确值"两类确定性错误答案被拦截，全部交回 LLM 正确作答 |

**每个机制的消融，都是"同一个模型，架构好一点，同一道题从错变对"的实证。**

## 五、评分规则对照（2026-08-20 官方知识库核对版）

官方知识库明示：**初赛完全采取客观评分**，按判分系统榜单排名；官方 judger 为
Intern-S 系列模型，结合参考答案 + final_response + trace 综合判定（不做正则/
字符串精确匹配，LaTeX 等价表达判一致）；无 partial 分公式公布、无逐题反馈。

| 规则 | 我们的对应 |
|------|-----------|
| 客观评分 = 正确题数 | 七机制榨干正确率；历史最佳 69/112（61.61 分） |
| judger 语义判分（结论 + 过程） | 证明题 final_response 保留完整过程（build_proof_body）；计算题附关键步骤（attach_steps）；trace 留全阶段审计证据 |
| 单题 20min / 全卷 6h / 并发 3 | 1200s 硬限 + PaperPacer 全卷预算池 + 单题请求硬上限 24 |
| 每天 2 次提交、无逐题反馈 | 16 题困难题校准集作为本地相对验证闭环（calibrate.py 一键 delta 对比） |
| 允许 SymPy/离线 RAG/多智能体；禁联网/Lean4 | sympy 预解器 + 18 领域定理离线 RAG + 12 节点 LangGraph 多智能体 |

## 六、可迁移性与扩展（对应"可扩展性"维度）

- **机制通用**：六大机制不绑定特定题型，可迁移到任意数学推理 / 代码生成 / 逻辑推理场景。
- **决赛多智能体扩展**：初赛的单智能体六机制，天然可拆分为多个 solver agent（每领域一个）+ 校验 agent + 仲裁 agent，符合决赛"多智能体协作"的赛题要求。
- **可持续扩展**：定理知识库模块化追加；确定性校验可扩展到更多符号工具（SymPy 之外）。

## 附：工程韧性（第一层"满分先决条件"的保证）

- 接口契约精确匹配（`__init__(self, client, *args, **kwargs)` + `solve -> dict`）
- 只经 `client.chat`，不读私有字段、不硬编码 key

- 单题 20 分钟分级预算 + 有限重试退避 + 兜底合法答案（"最终答案：未能求解"带标记可判分）
- 112 题全 status=success，零 invalid、零超时、零异常、零格式错误
