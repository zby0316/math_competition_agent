# VeritasMath：多径推理与确定性校验数学智能体

## —— 基于 Intern-S 系列模型的数学智能体设计与推理创新 · 参赛技术方案（V2.5）

> 题目编号 XH-202627 | 发榜单位：上海人工智能实验室

## 摘要

VeritasMath 是一个面向研究生级数学竞赛题的推理智能体，核心设计思想是：**在"锁单一模型 + 纯 API 调用 + 20 分钟单题硬限"的强约束下，用"多候选生成 + 确定性校验 + 过程审计"的架构，把模型能力内的正确率榨干到上限**。

官方评测（同题集 7f2499c5）轨迹：V1 53.53 分 → V2.4 **59.82 分（67/112）** → V2.9 53.57 分
（多候选采样反噬，已回退）→ **V2.5 61.61%（69/112，历史最佳，0 invalid/skipped/error，
1402 请求 / 203 截断 / 3h52m）**。V2.5 在 V2.4 最优基线之上叠加确定性计算前置（sympy
事前求解），官方实测拿下历史最佳后继续追加 **7 批修复**（det_solver 15 管线 / sympy
18 领域全覆盖 / 截断根治 / 解集守卫 / 零风险防御），再经 **cap 适配（max_tokens
≤8192）+ 超越 71 分改造（答案前置/官方别名表/首轮 550s/结论线索复用/socket 1200s）+
400 修复**（当前 HEAD `daa6911`），并补齐 18 子领域研究生级定理知识库，目标客观分在
61.61% 基础上继续提升 + 主观 40 分（三项 A 档）。

**一句话核心**：不是让模型"更努力地想"（思考模式实测反噬），而是让模型"在会做的题上绝不因架构而做错"。

## 一、任务理解与判分机制分析

### 1.1 任务

实现 `agent.solve(problem: str, metadata: dict) -> dict`，返回含非空 `final_response` 的可 JSON 序列化字典。平台注入官方 client，只经 `client.chat(messages, temperature, max_tokens)` 组织请求。

### 1.2 三条决定性事实（决定全部设计）

1. **评分 = 客观 60（正确率×60）+ 主观 40（推理策略 10 + 展示质量 20 + 创新性 10）**。客观分线性计分，每题约 0.54 分，错一题扣一题。
2. **judger 判"结论 + 过程合理性"，不是字符串匹配**。LaTeX 等价表达判对（-1/8 与 -1/8 分数形式一致），但"答案对而过程错"也会被判错。
3. **硬约束**：单题 20 分钟、全卷 6 小时墙钟、并发 3、慢 API 下私有 CoT 生成极慢（16384 token ≈ 811s）、禁联网/外部 API/Lean4、SymPy + 离线 RAG 可用。

### 1.3 历史评测的硬教训（V2.5 的设计依据）

同题集（7f2499c5）官方实测，correct / truncated / 墙钟：

| 版本 | 策略 | correct | truncated | 墙钟 |
|------|------|---------|-----------|------|
| V2.4 | prefill 直答（不思考） | **67** | 91 (10%) | 2.5h |
| V2.8 | thinking 深度思考 | 65 | 366 (33.8%) | 5h |
| V2.9 | 思考 + 多候选采样 N≥8 | 60 | 302 (19%) | 6.8h |
| V2.5 | prefill 直答 + sympy 事前求解 | **69** | 203 (14.5%) | 3h52m |

**结论**：在慢 API 下，"思考模式"和"大 N 采样"都会让 CoT 塞满 max_tokens → 答案截断 →
正确率反跌。**最优策略是 prefill 抑制 CoT（答案短、不截断）**，V2.5 再叠加确定性
计算前置，拿到官方历史最佳 61.61%；其残余 203 次截断引出后续修复批（见第六节）。

## 二、系统架构

### 2.1 三层提分架构

```
求解生成层          →   验证仲裁层           →   知识底座层
─────────────────────────────────────────────────────────
M2 prefill 直答         M5 三路交叉验证         M8 定理离线 RAG
M3 异构 B 路径          M4 SymPy 确定性校验     (18 子领域研究生级定理)
                       M6 过程审计 Critic       M9 流控预算护栏
                       M7 反思纠错
                       M10 成稿格式化交付
```

数据流：`题面 → 分类(题型×领域) → 双路求解(A prefill直答 + B 异构 + Python) → 三路交叉验证 → 确定性裁决 → 过程审计 → 成稿(含必要过程)`。

LangGraph 状态图，11 个模块（节点）协同，共享 state 字典。每节点有独立的时间/预算护栏，单题最坏路径受 20 分钟硬限约束。

## 三、核心机制（六大创新，对应主观分"创新性"维度）

### 机制一：prefill 抑制 CoT（确定性提速，不思考直答）

用 assistant 种子（`## 问题分析\n`）接管助手轮，让模型跳过私有推理链（reasoning_content）直接作答。**思考引导由提示词内化七点承担**（结构/覆盖/逻辑/自洽验证），不依赖不可控的 CoT 空想。

**为什么有效**：慢 API 下 CoT 计入 max_tokens 且生成极慢（811s/题），是截断和超时的元凶。prefill 直答答案短、快、不截断——**同题集实测：不思考 67 题 > 思考 65 题 > 采样 60 题**。

### 机制二：异构双方法推理 + 三路投票（打破同源一致地错）

A 路径（prefill 直答）与 Python 路径（SymPy 代码求解）**同源**（都是 S2），可能"一致地错"。B 路径用**异构方法提示**（DIVERSE_METHOD_HINT）强制换解法，提供方法论独立的第二证据。

三路投票的关键修复：**A=Python 一致时，若 B 反对，触发确定性裁决 A vs B（异构），而非放行"同源一致地错"**。这是纯字符串比对，零 token 成本。

### 机制三：确定性复算季后赛 Playoff（从"只能选"到"先算清楚再选"）

候选冲突时，不解原题，只做**候选代回核验**：方程回代看残差、极值比较目标函数实测值、计数缩小规模枚举对照、存在性实际搜索构造。产出的是**确定性证据**而非又一次采样判断。

**为什么有效**：语义仲裁只能从既有候选中选——两个都错时必输。Playoff 用确定性计算戳破"假一致"和"假反驳"。

### 机制四：SymPy 确定性校验（防止"答案对但过程错"）

judger 判"结论 + 过程"，答案对但中间步骤错也会判错。VeritasMath 用 SymPy 做确定性校验：候选答案代回题设条件验证、符号复核、assert 自调试——用确定性计算锚定过程正确性，而非依赖模型自报。

### 机制五：证据闸门（正确答案不被 Python 错答案覆盖）

Python 代回发现矛盾（FAIL/反例）时，**不得**用 Python 的错答案覆盖仲裁选定的正确答案。证据闸门拦截"Python 自报证据 ≠ 真实反驳"的情况，同时尊重 Playoff 的确定性裁决优先。

### 机制六：定理离线 RAG（开卷查定理，而非闭卷空想）

官方 18 个子领域（离散 24/数值 13/测度 11/微分几何 9 占一半分值）的研究生级定理，按"检索词 + 定理精确陈述 + 解题路线 + 易错点 + 分步算例"的模块速查格式注入提示词。让模型面对研究生级题（Sylow、Galois、留数、Rouché、CLT 等）时"开卷"而非空想。

## 附：工程韧性（第一层"满分先决条件"的保证）

- 接口契约精确匹配（`__init__(self, client, *args, **kwargs)` + `solve -> dict`）
- 只经 `client.chat`，不读私有字段、不硬编码 key

- **246 项单元与集成测试 + 30 项子测试全绿**（`pytest tests/`，零 API 调用）
