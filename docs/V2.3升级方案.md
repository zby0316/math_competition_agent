## 一、M10 TimeSaver 时间银行（时间控制到分钟级）

### 问题

PaperPacer 现在：简单题省的时间**被动**滚进池子，难题能否用到取决于"恰好跑到那"。
省下的时间**没有记账**，无法定向补给难题。

### 设计（升级 utils/paper_pacer.py）

```
时间银行 = 显式记账 + 定向补给：
  1. 每题标准预算（难度画像）：L1 120s / L2 240s / L3 480s / L4 720s
  2. 提前完成 → 差额入账（bank += standard - actual，仅当 actual < standard）
  3. 难题启动前：查余额 → 预算 = min(难度预算 + 余额，平台硬限 1200s)
  4. 全卷进度落后（pace > 1.15×）→ 银行冻结，优先保完成率
  5. 银行每笔交易入 trace（时间控制可审计）
```

### 效果

```
L1 简单题：301s → 90-120s，每卷省 ~1.5h
  → 时间银行显式补给 L3/L4 难题
  → 难题预算：L4 从 720s 可升级到 1000s+（深思考更充分）
  → 全卷墙钟：2.74h（V2）→ ~2.3h（V2.3），6h 余量更大
```

## 二、M11 AnswerGate 答案质量闸门（做得好）

### 问题

M7 只管证明题结构；**计算/推导题模型真算错**时，成稿前无人拦截（V2 的 8 个真错）。

### 设计（新增 utils/answer_gate.py）

```
成稿前 1 次 prefill LLM 自评（~10s，低成本）：
  评分维度（0-1 各维度）：
    - 结论明确性：最终答案是否显式给出
    - 步骤可核性：关键计算/推导是否可复核
    - 与题面对齐：是否覆盖题面全部要求
  综合分 < 阈值（0.6）→ 触发一轮"定向修复"（带缺陷清单重做）
  修复仍低 → 保留当前最佳（不无限循环，上限 1 轮）
```

### 成本与效果

```
触发：仅低质量答案（~20-30% 题）
每次：+10-20s（prefill）+ 修复轮（~60s，仅低分题）
收益：8 个真错 → 预期救回 4-6 个（"做得好"的直接保障）
```

## 三、M12 RecoveryBank 失败重试预算（环境容错）

### 问题

API 波动期 10 题"无法给出完整答案"——求解链路全挂，无兜底产出。

### 设计（升级 utils/llm_retry.py + user_agent.py）

```
全卷预留容错池（如 30 分钟）：
  1. 求解失败（final_response 为空/异常兜底）→ 记入重试队列
  2. 每完成若干题后检查队列 + 容错池余额
  3. 有余量 → 用"应急直答通道"（单次推理直接答，~60s）补跑失败题
  4. 容错池耗尽 → 停止补跑（优先保剩余题完成率）
```

### 效果

```
环境失败：10 题 → 预期 ≤2-3 题（大部分用应急直答救回）
成本：每卷 ≤30 分钟（预留池，不挤占主预算）
```

## 四、时间核算（6h 硬约束，分钟级）

| **墙钟合计** | **~2.3-3h** | 6h 内余量 50%+ |
| **单题上限** | ≤1200s | 平台硬限，永不下调 |
