## 一、V2.1 三大新机制

### M7【ProofDeepener 证明题深加工】—— L3/L4 核心攻坚

**问题**：L3/L4 多是证明/推导题，V2 的 DeepSolver 偏数值验证，对证明题无效（Python 无法验证证明）。

**设计**（新增 `utils/proof_deepener.py`）：
1. **证明结构强制模板**（零成本，图外后处理）：
   ```
   final_response 三段式：
   ① 定理陈述（题面重述 + 结论）
   ② 关键步骤链（编号步骤，每步引用已知定理/定义）
   ③ 结论（显式"证毕/结论："标记）
   ```
2. **证明完整性自检**（1 次 prefill LLM）：
   - 检测步骤链是否有逻辑跳跃
   - 检测结论是否显式给出
   - 缺失 → 补写（~512 token）
3. **双候选证明合并**：
   - 证明题也生成异构 B 路径（已有）
   - 两路证明合并 → 取"步骤链更完整"者

**成本**：仅 L3/L4 证明题触发（~15% 题），每次 +1 次 prefill（~10s）。
**预期**：L3/L4 证明题正确率 +15-25pp。

### M8【FastLane 快速通道强化】—— 省时间给难题

**问题**：L1/L2 平均 301s/题偏慢，挤占 L3/L4 的深思考时间。

**设计**（改 `utils/confidence_gate.py` + `fan_out`）：
1. **L1 客观题单路径**：分类确认 L1 + 置信高 → 只跑 1 次推理 + 规则校验（省 Python/critic）
2. **L2 简化双路**：跳过 Critic 审计（推理 + Python 验证足够）
3. **省下的时间**：滚动进 PaperPacer 预算池 → 全部给 L3/L4

**预期**：L1/L2 平均 301s → **90-120s**，每卷省出 ~1.5h 给难题。

### M9【判分稳定性加固】—— 消除 RuntimeError 假错

**问题**：判分 API 波动导致 10 题 RuntimeError 假错（重判后可翻正）。

**设计**（改 `local_test/grade_llm.py`）：
1. **判分失败自动重试**（最多 3 次，指数退避）
2. **RuntimeError 不判 wrong**：标记 `grade_error`，纳入待重判队列
3. **批量判分完成后再统一重判**未成功项

**预期**：判分成功率 100%，消除环境类假错。

## 二、时间预算设计（6h 硬约束核算）

### 分级预算表

| 难度 | 题数占比 | 单题预算 | 全卷耗时 |
|---|---|---|---|
| L1 | ~20%（22 题） | 90-120s | ~40min |
| L2 | ~35%（40 题） | 180-240s | ~2h |
| L3 | ~30%（34 题） | 300-600s | ~3h |
| L4 | ~15%（16 题） | 600-900s | ~2.5h |

**总计约 5h（含并发 3 并行加速实际 ~2.5-3h 墙钟）**——6h 上限余量充足。

### 单题 20min 硬约束（1200s）

```
L4 最难题 900s < 1200s ✅（余 300s 给应急直答）
PaperPacer 落后收紧机制保障：任何题不超 1200s
```

### 关键保障链

```
M8 快速通道（L1/L2 省 1.5h）
  → 预算池滚动
  → M7 ProofDeepener（L3/L4 深加工 ≤15% 题）
  → M1 PaperPacer 全局兜底（绝不超时）
```
